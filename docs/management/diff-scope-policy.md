# Diff Scope Policy

## Purpose

Task境界を守りつつ、実装時に判明する必要変更を許容する。

## Core Rule

差分適否は「事前の固定ファイル数」ではなく「Task目的への整合性」で判定する。

## Execution Rule

1. Task開始時は対象ファイルを厳密固定しない。
2. 代わりに Task目的（何を達成するか）を固定する。
3. 実装中に追加変更が必要になった場合は、変更ファイルごとに「目的に必要な理由」を記録する。
4. 完了時に実差分を確定し、結果ファイルの変更一覧を実態と一致させる。

## Review Rule

- 目的達成に不要な変更は差し戻し対象。
- 受け入れ条件（例: `npm run build` 成功）を満たしていること。
- 結果記録と実差分が一致していること。

## Prohibited

- ついで修正（目的外変更）
- 記録と実差分の不一致
